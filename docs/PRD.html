1. Product Overview

Ergane is an invention detection assistant for engineering teams. It runs on every git push, analyzes code diffs for potential patentable technical improvements, searches patent databases in parallel, synthesizes prior art similarity, drafts preliminary claim language, and notifies teams — all with a mandatory human review gate.

LEGAL POSITIONING (NON-NEGOTIABLE): Ergane is an assistant, not a replacement for patent attorneys. Every output carries a disclaimer. The tool never claims to guarantee patentability and never auto-files patents.

1.1 Problem Statement

  • Engineers invent patentable technical improvements in code every day
  • They don't know it — patentable subject matter is invisible to non-lawyers
  • By the time legal review happens (if ever), the invention is shipped, blogged about, or committed to public repos — destroying patentability
  • Prior art search is expensive — patent attorneys charge $5K–$15K for a single prior art opinion
  • Early detection is everything — filing before public disclosure preserves foreign rights under the Paris Convention

1.2 Solution Statement

Ergane moves invention detection left into the engineering workflow. Instead of waiting 6–12 months for a legal review, every commit is automatically screened. When a potential invention is detected:

  1. Technical problem and solution are extracted
  2. Prior art is searched across USPTO, EPO, and PQAI in parallel
  3. Novelty assessment and draft claim are generated
  4. Team is notified via OpenClaw (slack/discord)
  5. Human attorney review is gated — nothing auto-files

3. User Stories

US-001: Automatic Invention Detection MVP

As an engineer, I want every commit to be automatically screened for patentable inventions, so that I don't need to be a lawyer to identify IP value in my code.

AC: Given a git push → When Ergane runs → Then inventions with novelty_score ≥ 0.4 are flagged with structured output.

US-002: Structural Output for Legal Review MVP

As a patent attorney, I want a structured disclosure document with technical problem, solution, prior art comparison, and draft claims, so that I can provide an opinion without reinventing the analysis.

AC: Given an invention detected → When I open the GitHub PR → Then I see: (1) Technical Problem, (2) Technical Solution, (3) Novelty Score, (4) Top 10 Prior Art patents with similarity scores, (5) Draft Independent Claim.

US-003: Parallel Patent Database Search MVP

As an engineer, I want Ergane to search USPTO, EPO, and PQAI simultaneously via a single SQL query, so that prior art search is fast and comprehensive.

AC: Given an invention description → When Coral executes → Then results from USPTO + EPO + PQAI are returned in a unified table within 10 seconds.

US-004: Slack Notification MVP

As a team lead, I want to be notified in Slack when a novel invention is detected, so that I can review and forward to legal promptly.

AC: Given an invention with novelty ≥ 0.7 → When synthesis completes → Then OpenClaw posts a Slack message with novelty gauge, prior art link, and "Review Draft" button.

US-005: Human Review Gate MVP

As a legal counsel, I want to approve or reject every flagged invention before any filing action, so that only defensible disclosures proceed.

AC: Given an invention detected → When Ergane completes → Then a GitHub PR comment is opened with "needs-attorney-review" label. No auto-filing occurs.

US-006: Invention Memory STRETCH

As a CTO, I want all detected inventions stored in a searchable knowledge graph, so that I can query what Alice invented last month or what relates to a specific patent family.

AC: Given a query "What inventions did Alice create in June 2026?" → When GBrain hybrid search runs → Then relevant invention notes are returned with typed links.

US-007: Agentic Notification JUDGE

As a judge at a hackathon, I want to see that the notification layer is not just a webhook but an agent that decides what to do, so that I understand the technical depth of the project.

AC: Given an invention notification → When OpenClaw receives it → Then an agent turn runs that decides channel, urgency, and can ask follow-up questions.

5. Legal Requirements

⚠️ THESE CONSTRAINTS ARE PRODUCT FEATURES, NOT BUGS. Compliance with legal reality is what differentiates Ergane from snake-oil "AI patent" tools.
IDConstraintImplementationStatus
LR-001Software/code per se is NOT patentable (Alice Corp, §101)System claims language: "A method comprising...", "A system comprising..." — never "A program..."REQUIRED
LR-002AI cannot be a co-inventor (USPTO Nov 2025 guidance)All outputs say "Preliminary draft for attorney review only." Human (engineer) is sole inventor.REQUIRED
LR-003GitHub code is NOT USPTO-recognized prior artGitHub used only for product validation. Prior art claims sourced only from USPTO/EPO databases.REQUIRED
LR-004Disclaimer on every output"This tool identifies potential technical inventions. It does not provide legal advice. Consult a patent attorney." — in CLI, PR comment, and README.REQUIRED
LR-005No auto-filingErgane NEVER files patents, sends forms to USPTO, or acts as a legal representative. Maximum action: open GitHub PR for human review.REQUIRED
LR-006Confidentiality: local-firstNo generic OpenAI API training on user data. All code analysis done via API with no-retention. Local patent corpus preferred over cloud queries where possible.REQUIRED
LR-007Permission-gated repo accessErgane NEVER processes code from private repos without explicit opt-in in config.REQUIRED
