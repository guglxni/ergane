# Ergane Invention Detection

## Purpose
Analyze code diffs (from PyGit2) and Graphifyy AST subgraphs to identify potential patentable technical improvements to computer functionality.

## Input Schema
```json
{
  "diff": "git diff patch string",
  "commit_message": "string",
  "subgraph": { "nodes": [...], "edges": [...] },
  "files_changed": ["src/cache/invalidator.py", "src/consensus/vector_clock.py"]
}
```

## Output Schema
```json
{
  "technical_problem": "Inconsistent cache state during network partitions",
  "technical_solution": "Vector clock-based invalidation protocol with monotonic counters",
  "novelty_score": 0.87,
  "novelty_assessment": "HIGH",
  "key_claim_elements": [
    "maintaining a vector clock per cache node",
    "comparing vector clocks to detect stale entries",
    "atomic invalidation when partition heals"
  ],
  "rationale": "This is a novel algorithmic improvement to distributed cache consistency...",
  "ipc_suggestion": "G06F12/08",
  "skip": false
}
```

## Scoring Rules
- HIGH (0.7-1.0): Novel algorithm, architectural improvement, or technical optimization with no obvious prior art.
- MEDIUM (0.4-0.69): Improvement on known technique with non-obvious twist.
- LOW (0.0-0.39): Routine implementation, standard library usage, UI change, business logic.

## Legal Constraints
- Software per se is NOT patentable (Alice Corp §101). Claim the method/system.
- NEVER output legal advice. Only technical analysis.
- ALWAYS include: "Preliminary draft for attorney review only."
- AI cannot be a co-inventor (USPTO Nov 2025).

## References
- references/alice-corp.md — Alice Corp v. CLS Bank summary
- references/uspto-101.md — Patent eligibility guidance

# Ergane Prior Art Search

## Purpose
Generate Coral DSL v3 compatible SQL to search USPTO, EPO, PQAI, and local patent corpora in parallel.

## CORAL DSL v3 SYNTAX (verified)
- Top-level key: `functions:` NOT `table_functions:`
- Function args: `args:` NOT `arguments:`
- Arg binding: `bind: {arg: name}` NOT `type: Utf8`
- Search limits: `default_top_k`, `max_top_k`, `max_calls_per_query`
- Request body: array with `path:`, `from: arg`, `key:`
- Response: `rows_path: []` and explicit `columns: []`

## Available Sources
| Source | Table/Function | Auth | Query Syntax |
|---|---|---|---|
| USPTO | uspto.patents | X-API-KEY header | Solr-like field:value |
| EPO | epo.patents | OAuth2 Bearer | CQL: ti=title, ab=abstract |
| PQAI | pqai.search_patents(query => '...') | Optional token | Natural language semantic |
| Local | local_patents.grants | None (parquet) | SQL WHERE clauses |

## SQL Pattern
```sql
WITH uspto_results AS (
    SELECT patent_number, title, abstract, assignee, 0.8 AS source_weight
    FROM uspto.patents WHERE q = '{query}' LIMIT 10
),
epo_results AS (
    SELECT doc_number AS patent_number, title, abstract, applicant AS assignee, 0.8 AS source_weight
    FROM epo.patents WHERE q = '{cql_query}' LIMIT 10
),
pqai_results AS (
    SELECT publication_number AS patent_number, title, abstract, NULL AS assignee, score AS source_weight
    FROM pqai.search_patents(query => '{natural_query}', top_k => 10)
)
SELECT * FROM uspto_results
UNION ALL SELECT * FROM epo_results
UNION ALL SELECT * FROM pqai_results
ORDER BY source_weight DESC
LIMIT 20;
```

## Rules
- Always query ≥2 sources for cross-validation.
- Use source_weight for ranking (PQAI score highest priority).
- Escape user query for SQL injection.

# Ergane Synthesis & Claim Drafting

## Purpose
Compare a detected technical invention against Coral prior art results, assess novelty, and draft preliminary claim language.

## Input
- Invention JSON (from $ergane-detect)
- Prior art table (from $ergane-prior-art) — markdown format

## Output
```json
{
  "overall_similarity_score": 23.0,
  "closest_patent": {
    "patent_number": "US10,123,456",
    "title": "Method for distributed cache synchronization",
    "source": "USPTO",
    "similarity_score": 18.0,
    "overlapping_claim_elements": ["network partition detection"]
  },
  "risk_assessment": "NOVEL",
  "analysis": "The vector clock approach is not anticipated by US10,123,456 which uses timestamps...",
  "draft_independent_claim": "1. A method for distributed cache invalidation comprising...",
  "recommendation": "PROCEED_WITH_FILING",
  "disclaimer": "This is a preliminary draft for attorney review only."
}
```

## Claim Drafting Rules
1. Independent claim (Claim 1): Include ALL essential elements.
2. Dependent claims (Claims 2-4): Add optional but valuable limitations.
3. Language: "A method comprising...", "A system comprising..."
4. NEVER claim software per se.
5. ALWAYS include disclaimer.

## Risk Assessment Scale
- NOVEL (similarity < 40%): Strong candidate for filing.
- POSSIBLY_NOVEL (40-70%): Needs refinement or narrower claims.
- LIKELY_PRIOR_ART (> 70%): Consider abandonment or major redesign.
