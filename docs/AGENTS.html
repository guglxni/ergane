1. Philosophy

"You shouldn't be prompting coding agents anymore. You should be designing loops that prompt your agents."
— Peter Steinberger, "Clawfather" (OpenAI, creator of OpenClaw)
"I don't prompt Claude anymore. I have loops running that prompt Claude and figuring out what to do. My job is to write loops."
— Boris Cherny, Head of Claude Code, Anthropic

Loop Engineering is the practice of replacing yourself as the person who prompts the agent and instead designing the system that does it. A loop is a recursive goal: you define purpose, and the AI iterates until complete.

The leverage point moved from prompt engineering (writing good prompts) to loop design (designing systems with verifiable stop conditions, isolation, verification, and state persistence).

3. Ouro Loop Verification Gates

From VictorVVedtion/ouro-loop — structured autonomous loop with guardrails.

pip install ouro-loop
ouro-sentinel init .        # scan project, generate partitions + config
ouro-sentinel install .     # install runner + dashboard scripts
ouro-sentinel status .      # check iteration/findings/coverage
GateFull NameCheckErgane Application
G1EXISTOutput exists and is non-emptyDetection JSON contains technical_problem, technical_solution, novelty_score fields. Empty → reject immediately.
G2RELEVANCEOutput addresses actual problemIPC suggestion matches file domain (e.g., G06F for compute). Commit message semantically aligns with diff content.
G3ROOT_CAUSEFixes right thing, not symptomNovelty assessed for underlying technical improvement (algorithm/architecture), not surface code change (variable rename).
G4MOMENTUMProgress measurable since last iterationCoral returns ≥1 result per source. Similarity score decreases vs previous run for same invention domain.
G5RECALLLoop remembers what was doneergane-state.md updated with invention ID, date, novelty score, status. Next run reads state before starting.
Gate Enforcement: Each subagent's output MUST pass all 5 gates before flowing to the next stage. Failed gate → retry (max 3) → escalate to human inbox if still failing.

4.2 Three-Phase Adaptive Workflow

Phase 1: Inception
  • Clarify requirements and constraints
  • Set acceptance criteria (verifiable stop conditions)
  • Create loop contract (11-part)
  • Choose subagent model assignments
Phase 2: Construction
  • Agent runs with maker ≠ checker split
  • Each subagent in isolated worktree
  • State written to disk after every turn
  • Ouro Loop gates checked at phase boundaries
  • Boundaries enforced: time limit, token limit, scope limit
Phase 3: Transition
  • Final verification against stop conditions
  • Human review before any merge (NEVER auto-merge unattended)
  • State archived for tomorrow's run
  • Escalation inbox updated if work is stuck or risky

5. Ergane Loop Contract (11-Part)

EVERY loop MUST define these 11 elements before running. No exceptions.

#ElementErgane DefinitionValidation
1PurposeDetect patentable technical inventions in code commitsMust fit in one sentence
2TriggerGit push (GitHub Action) or manual ergane scanMust be specific event, not "when I feel like it"
3Triage criteriaNovelty score ≥ 0.4 AND key_claim_elements non-empty AND IPC suggestion presentAll three must be true
4BoundariesNEVER auto-file patents. NEVER process private repos without permission. NEVER claim software per se is patentable.Hard-coded in RULES.md
5Stop conditions(a) ergane scan exits 0, (b) novelty_score < 0.4 for all diffs, (c) timeout after 300 secondsVerifiable, not subjective
6Turn/time limit300 seconds per pipeline. Max 20 patent records from Coral. Max 3 LLM calls per run.Safety bound against infinite burn
7Skill dependencies$ergane-detect, $ergane-prior-art, $ergane-synthesize (mandatory). $ergane-notify (optional).Skills must exist in ~/.hermes/skills/ or repo skills/
8Connector dependenciesCoral MCP running. GitHub token present. OpenAI API key valid.Pre-flight check before loop starts
9Verification gateOuro Loop: EXIST + RELEVANCE + ROOT_CAUSE + MOMENTUM + RECALLGate output logged to state file
10Escalation pathBlocked work → GitHub PR comment with "needs-attorney-review" label. Human reviews within 48h.No auto-approval, ever
11State file location.github/ergane-state.mdMust be in version control

6.1 Explorer Agent — Code Understanding

; .codex/agents/explorer.toml
name = "Ergane-Explorer"
description = "Reads code diffs and Graphifyy subgraphs to identify technical problems and solutions"

instructions = """
You are a technical code analyst specializing in identifying patentable improvements
to computer functionality.

INPUT FORMAT:
- Code diff: {diff}
- Commit message: {commit_message}
- Graphifyy subgraph: {subgraph}  (JSON with function/class nodes and edges)
- Files changed: {files_changed}

YOUR TASK:
1. Identify the technical problem being solved (not the business problem).
2. Identify the technical solution implemented.
3. Assess whether this is a novel improvement to computer functionality,
   not merely an abstract idea, business method, or routine implementation.

OUTPUT: Strict JSON only:
{
  "technical_problem": "string",
  "technical_solution": "string",
  "novelty_score": float (0.0-1.0),
  "novelty_assessment": "HIGH|MEDIUM|LOW",
  "key_claim_elements": ["string"],
  "rationale": "string explaining patentability assessment",
  "ipc_suggestion": "string (suggested IPC/CPC code)"
}

RULES:
- HIGH: novel algorithm, architectural improvement, or optimization with no obvious prior art.
- MEDIUM: improvement on known technique with non-obvious twist.
- LOW: routine implementation, standard library, UI change, business logic.
- If novelty_score < 0.4, set "skip": true.
- NEVER output legal advice. Only technical analysis.
"""

model = "openai/gpt-5.6-luna"
thinking = "medium"

name = "Ergane-Implementer"
description = "Generates Coral DSL v3 SQL for patent prior art search and executes searches"

instructions = """
You generate Coral DSL v3 compatible SQL for patent prior art search.

CORRECT CORAL SYNTAX (validated against withcoral.com/docs):
- Use `functions:` not `table_functions:`. Use `args:` not `arguments:`.
- HTTP function args use `bind: {arg: name}` pattern.
- Search limits use `default_top_k`, `max_top_k`, `max_calls_per_query`.
- Request body uses array with `path:`, `from: arg`, `key:` entries.
- Response columns must be explicitly declared.

AVAILABLE SOURCES:
- uspto.patents — US applications filed since 2001 (POST /api/v1/patent/applications/search)
- epo.patents — EPO documents (GET /rest-services/published-data/search, CQL syntax)
- pqai.search_patents — Semantic search (GET /search/102)
- local_patents.grants — Local parquet corpus

GENERATE SQL PATTERN:
WITH source_a AS (SELECT ..., weight FROM uspto.patents WHERE q = '...' LIMIT 10),
     source_b AS (SELECT ..., weight FROM epo.patents WHERE q = '...' LIMIT 10),
     source_c AS (SELECT ..., weight FROM pqai.search_patents(query => '...') LIMIT 10)
SELECT * FROM source_a UNION ALL ... ORDER BY weight DESC LIMIT 20;

OUTPUT: The SQL query string only. No prose.
"""

thinking = "medium"

7. Skill Definitions



Skills live in skills/ (repo) or ~/.hermes/skills/ (Hermes). Each is a folder with SKILL.md.



7.1 $ergane-detect


# skills/ergane-detect/SKILL.md
---
name: ergane-detect
trigger:
  - "analyze this diff for patentable inventions"
  - "what technical improvements are in this commit"
  - "detect inventions"
---

# Ergane Invention Detection

Analyze code diffs to identify potential patentable technical improvements.

## Input
- Git diff patch
- Commit message
- Graphifyy AST subgraph (JSON)
- List of files changed

## Output
JSON with: technical_problem, technical_solution, novelty_score (0-1),
novelty_assessment (HIGH/MEDIUM/LOW), key_claim_elements[], rationale,
icp_suggestion.

## Rules
- Software per se is NOT patentable (Alice Corp §101).
- Only flag POTENTIAL inventions. Never claim guaranteed patentability.
- Include disclaimer: "Preliminary draft for attorney review only."




7.2 $ergane-prior-art


# skills/ergane-prior-art/SKILL.md
---
name: ergane-prior-art
trigger:
  - "search patent databases"
  - "find prior art for this invention"
  - "coral sql for patents"
---

# Ergane Prior Art Search

Generate Coral DSL v3 SQL to search patent databases.

## Available Sources
- uspto.patents — US applications (free, data.uspto.gov)
- epo.patents — EPO documents (free, developers.epo.org)
- pqai.search_patents — Semantic search (free, api.projectpq.ai)
- local_patents.grants — Local corpus (optional)

## Output
Valid Coral SQL query. Must use corrected DSL v3 syntax:
`functions:`, `args:`, `bind:`, `default_top_k`, etc.

## Rules
- Parallel search across ≥2 sources per query.
- Limit to 10 per source, 20 total.
- Use UNION ALL with source_weight for ranking.

8. Worktree Isolation



Every subagent MUST run in its own worktree. Two agents writing the same file is the exact same headache as two engineers committing to the same lines.



#!/bin/bash
# worktree-manager.sh — isolate subagent checkouts

REPO_ROOT=$(git rev-parse --show-toplevel)
AGENT_ID=${1:-agent-$(date +%s)}
WORKTREE="$REPO_ROOT/.worktrees/$AGENT_ID"

# Create worktree
git worktree add --detach "$WORKTREE"
cd "$WORKTREE"

# Run agent task
# ... (agent code here) ...

# Merge results back (if approved)
git add .
git commit -m "Ergane: $AGENT_ID analysis"

# Cleanup
cd "$REPO_ROOT"
git worktree remove "$WORKTREE"
rm -rf "$WORKTREE"

10. Anti-Patterns (NEVER)




  
Anti-PatternWhy It FailsErgane Guardrail

  
"The code is good" as stop conditionSubjective, unverifiableStop = ergane scan exits 0 OR novelty < 0.4 OR 300s timeout

  
No turn/time limitInfinite token burnHard limit: 300s, 3 LLM calls, 20 patent records

  
Writer grades own workFalse positives, low qualityMandatory verifier agent with different model

  
No state fileEvery run starts from zeroState written after every detection

  
Auto-merge without human reviewComprehension debt, legal riskNEVER auto-merge. PR comment only.

  
Cognitive surrenderStop having opinionsRULES.md: "I flag POTENTIAL only. Human finalizes."
